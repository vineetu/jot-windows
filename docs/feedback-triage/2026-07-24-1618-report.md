## 1. Transcripts can leak into feedback reports (privacy) — highest severity

The report header promises `transcripts redacted`. For multi-line dictations, that promise is false.

- `RecorderController.cs:237` logs `SAVED: "{TitleFrom(text)}" ({len} chars)`.
- `TitleFrom` (`RecorderController.cs:326`) splits on `' '` **only** — never on `\n`.
- Multi-line transcripts are not hypothetical: `Text/ModelArtifactScrubber.cs:35` is explicitly written to **preserve interior `\n\n`** ("keeps its break"). Paragraph breaks are a designed Nemotron output.

So a title containing `\n` writes one logical entry as several *physical* lines. `FeedbackReport.TailOfLog` (`FeedbackReport.cs:80`) reads with `File.ReadLines`, and `Scrub` runs per physical line:

- **First fragment** — has the `SAVED: "` marker, but the only quote on the line is the opening one, so `close == open`, the `close > open` guard at `FeedbackReport.cs:100` is false, and it **silently fails open**: no redaction, raw words shipped.
- **Trailing fragment** — no `SAVED: "` marker, so `Scrub` skips it entirely; ships raw plus the closing `" (200 chars)`.

Failing *open* is the sharp edge — a guard meant to protect dictated text does nothing when it doesn't recognize the shape. Bounded to the first ~6 tokens, but that's still user speech leaving the machine under a header claiming it didn't.

`tests/Jot.Tests/FeedbackReportTests.cs` covers quotes-inside-transcript, username, and no-op lines — every case is single-line. The multi-line case is untested.

## 2. The test suite writes into the real user's activity log

`DataFolderMigrator.cs:116,124` and `StartupMigration.cs:66,89` call `JotLog.Info` unconditionally. `DataFolderMigratorTests` / `StartupMigrationTests` exercise that code, and `JotLog._dataDirProvider` is never initialized in the test host — so `LogsDir()` falls back to `JotPaths.AppDataRoot` (`JotLog.cs:50`) and appends to the developer's live `%LOCALAPPDATA%\Jot\logs\jot.log`.

Visible in this payload: ~14 of the 120 shipped lines are `jot-migtest-*` / `jot-migtest2-*` temp-path noise from `dotnet test`. The report also says `(older lines trimmed to fit)` — meaning **real session diagnostics were evicted from the 6,000-char budget to make room for test noise**. This degrades every report submitted from a machine that has run the suite, and inflates the rotation rate of a 256 KB log.

## 3. The E2E test validated a stale binary

The report says `app: 0.3.0.0`, but `Jot.csproj:14` is `<Version>1.2.1</Version>` — with no `AssemblyVersion`/`FileVersion` override anywhere in the repo (only an unrelated `0.3.0` mention in a docs file). The last commit is "Release 1.2.1.0". Both version sources agree with each other (`FeedbackClient.cs:30` uses `GetEntryAssembly()`, `FeedbackReport.cs:39` uses `typeof(FeedbackReport).Assembly`), so this is one stale build, not a mismatch — today's test ran against a months-old binary and its diagnostics are attributed to 0.3.0.0.

Minor, same area: those two call sites are independent version sources. They agree in this WPF app, but `GetEntryAssembly()` can return null in other hosts, degrading to `"?"`.

## Suggested priority

1. Finding 1 — privacy, and the fix is small (strip newlines in `TitleFrom`, plus make `Scrub` fail *closed* when it sees `SAVED: "` without a valid closing quote). Both directions matter: the first stops new bad lines, the second protects against lines already on disk.
2. Finding 2 — redirect `JotLog` to a temp dir in test setup.
